Methodology & provenance

What this is

SFERA Lab is a research instrument, not a commercial product. This page computes real Western tropical natal charts and displays them with their conventions labeled. It generates no AI text. It exists because the SFERA research program needs a verified deterministic calculation layer, and because a free, honest chart tool is genuinely useful. This is a Research UI, deliberately not a finished product interface.

Calculation method

Planetary positionsastronomy-engine 2.1.19 (MIT, analytic ephemeris — the same library version as the verified Python kernel), geocentric ecliptic-of-date longitudes; retrograde states from numeric 1-hour central-difference speeds.
Time zonesIANA tzdb via the browser/Node Intl database — the authoritative source for historical offsets, DST and LMT-era births. Nonexistent local times (DST spring gaps) are rejected, not silently shifted. Ambiguous fall-back times are labeled and resolved explicitly (fold 0/1). The zone identity (e.g. Asia/Yekaterinburg) comes from the place-resolution result, never inferred from a current UTC offset.
HousesNative formulas for ASC/MC and Placidus, equal and whole-sign systems, computed in your browser. House systems genuinely disagree away from the angles — that is a documented feature of the tradition; the system used is always labeled. Koch, Regiomontanus and Campanus are computed by the Python lab kernel but are not implemented in this browser build (honestly absent, never approximated).
Lunar nodesMean node via the analytic secular formula. The true (osculating) node requires the lab kernel's library and is suppressed here.
AspectsMajor aspects (0/60/90/120/180) with one documented natal orb set (config orbs-v0.1); the convention is disclosed rather than hidden.
Suppression ruleUnknown birth time → Moon degree, angles and houses are suppressed, never approximated. Beyond ±66° latitude angles and houses are suppressed (school-dependent to the point of being undefined).

Verification (two layers, both frozen and committed)

Python kernel sfera-western 0.1.0 vs Swiss Ephemeris (pyswisseph) + published oracle anchors (equinoxes/solstices/new moons) results_differential_2026-09-12.json — 51 frozen verification cases, max cross-engine delta 0.0051°. Engine-vs-engine agreement is NOT proof of truth, and is labeled as such.
This browser port (sfera-western-js 0.1.0-js.1) vs the Python kernel results_differential_js_2026-09-13.json — 260 frozen cases (positions, 16 historical time-zone batteries, 192 house-system cases across 8 latitudes, mean node, full-chart pipelines, byte-level reading-template comparison): 0 failures. Layer maxima: positions 0° (same library lineage — not an independent cross-check; the independent cross-engine check is the Python kernel's 0.0051° vs Swiss Ephemeris) · time zones 0 s · houses 0.0001° · mean node 0.0048°. The committed record and fixture are in the public repository.

School & convention labels

Western tropical astrology is not one thing. Where a convention matters (house system, orb set, node type), this tool shows which one was used. The only interpretive surface is the labeled static template, which lists calculated positions and deliberately suppresses what is unknown — it makes no claims beyond the chart's geometry.

Research status (honest)

The lab has run an internal quality benchmark of AI interpretation (X-01-Z) and maintains an evidence database and claim ledger — see the live research status page, generated from the repository. What is not validated: human practitioner acceptance, the engine bet on voluntary return, willingness to pay. No research claims are made beyond what exists.

Privacy

The calculation runs in your browser; birth data never leaves your device; there is no server to receive it. Full explanation: privacy page — including an honest description of what the place search sends.

Place resolution disclosure

Place search uses a hybrid: a small bundled city list (coordinates ≈±1 km, verification class UNVERIFIED_COMPILED_LIST) plus the global Open-Meteo/GeoNames gazetteer (CC-BY 4.0; the query is sent only when you search; gazetteer precision is roughly a kilometer, less for small localities). The time zone is taken as an IANA identity and applied with the full historical tzdb. For archival precision, enter latitude/longitude and the time zone manually. Suggestion ranking: exact matches outrank prefix matches, which outrank one-letter variants («Кагул» ↔ «Кахул»); a large city (≥100k) is promoted above an unpopulated same-spelling hamlet — all options remain listed, only the order changes. Place-resolution regression cases (incl. Tyumen and Cahul) are frozen in the lab repository.
