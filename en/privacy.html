SFERA Lab — privacy explanation (research prototype)

This is the plain-language privacy explanation for the public SFERA Lab generator ( EXECUTION_003 Part 3 ). It deliberately is not a lawyer-style privacy policy, and it does not claim GDPR compliance. It describes what the system actually does.

What input is used

The natal chart form asks for a birth date, an optional birth time, a place (city lookup from a global gazetteer, or latitude/longitude), a time zone, an optional house system, and an optional free-text question.

The calculation runs entirely inside your browser. Your birth data is processed by JavaScript on your device and is never transmitted to us or to anyone else. There is no server that could receive it.

Birth-place search: what leaves the device

If you use the city search, the typed place-name text is sent as a query to the Open-Meteo Geocoding API (data from the open GeoNames catalog, CC-BY 4.0) to resolve coordinates and the IANA time-zone identity. In doing so:

  • your birth date, birth time, question, any chart data, and any telemetry identifiers are not sent;
  • the request carries no account cookie (none exists) and no credentials;
  • you can avoid the request entirely: a small bundled city list works offline, and coordinates plus time zone can always be entered manually.

If you enter latitude/longitude manually instead of searching, no place-related request is made at all.

Whether input is retained

  • Birth data: not retained anywhere by us — not on a server (there is none), not in storage. It exists only in the memory of your browser tab until you close or reload the page.
  • We cannot recover, reproduce, or look at your chart after you leave the page. Nothing is linked to you, because nothing about you reaches us.

What telemetry is collected

  • Without your consent, nothing is transmitted — not even the fact of a visit. No analytics service receives data without the explicit consent checkbox. If you tick the box mid-session, the stages already reached in this session are replayed from page memory — nothing beyond this session, no birth data.
  • With consent (the checkbox in the form), anonymous usage events of this research prototype may be sent to a minimal research sink (a Cloudflare Worker), deployed only by explicit founder authorization. An event contains: the stage name (e.g. traffic_in, birth_start, calc_complete, reading_consumed), a timestamp, a random session id (dies with the tab), a traffic class (human/bot, derived without storing the User-Agent string), interface language, device class (mobile/desktop), the link's source tag (e.g. personal, telegram), and technical calculation flags. Additionally, after a result is rendered: whether the reading was actually consumed (defined behaviorally: the reading text was scrolled into view, or the page stayed visible for 20 s — rendering alone never counts), optional anonymous answers to 5 short experience questions (stored separately from the funnel; only a random session id links them to it), and an explicit "share the tool" action (only on your click).
  • A persistent visitor id is created only after consent and serves exactly one purpose: distinguishing a voluntary return visit from the first visit (return_visit). It is random, never linked to birth data, never used for advertising, never joined with other services. How to delete it: untick the consent box — the identifier is erased from your browser; or clear this site's data in your browser settings.
  • The sink is configured to not store IP addresses: the server necessarily sees the request IP (like any web server) but does not record it; only the request's country code (from the Cloudflare network) is stored. Event contents are strictly schema-validated; birth-data fields are rejected.
  • No telemetry or history of any kind is ever used as input to any calculation or reading. This is a standing rule of the SFERA Lab.
  • Your consent choice is stored in your own browser (localStorage), so the form can remember your answer. You can clear it any time via your browser settings.
  • Infrastructure note (honesty): the site is served as static files by GitHub Pages (GitHub/Microsoft); the telemetry sink (if connected) runs on Cloudflare Workers. Like any host, they record their own request logs (e.g. IP address, user agent) under their own policies for security and abuse prevention. That logging is outside this project's control, and this project never receives it.

What consent changes

Consent never enables anyone to see your birth data or your question — by construction, they never leave your device. It only allows the anonymous stage counting described above.

This is an experimental Lab surface

This is a research instrument, not a commercial product, and not a finished service. It may change, break, or be taken offline without notice. It is not the final SFERA product.

How to stop participating

Just stop using the page — there is nothing stored about you to delete. To also remove the consent marker from your own browser, clear this site's data in your browser settings. We hold no data we could delete on request, because we receive none.

Scope

18+ only. If you submit someone else's birth data, that is your responsibility — we never receive or store it anyway.
